# Inkwell Backend

Async FastAPI foundation for Inkwell, backed exclusively by PostgreSQL. The domain modules are
intentionally scaffolded but do not expose article-generation behavior yet.

## Prerequisites

- Python 3.12
- [uv](https://docs.astral.sh/uv/)
- Docker with Docker Compose

## First-time setup

```powershell
Copy-Item .env.example .env
uv sync
docker compose up -d postgres
uv run alembic upgrade head
```

Replace `JWT_SECRET_KEY` in `.env` with a random secret before sharing or deploying the app.

## Run the API

```powershell
uv run uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`, with interactive documentation at `/docs`.

- `GET /health` checks the API process without contacting PostgreSQL.
- `GET /ready` checks PostgreSQL connectivity with `SELECT 1`.
- `/api/v1` is reserved for the scaffolded domain routers; it exposes no operations yet.

## Database migrations

Create a migration after importing new model modules from `app/db/models/__init__.py`:

```powershell
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Inspect every autogenerated migration before applying it. To undo one revision:

```powershell
uv run alembic downgrade -1
```

## Tests

Fast tests do not require a running database:

```powershell
uv run pytest -m "not database"
```

The database integration tests use a separate, temporary PostgreSQL service on port `5433`:

```powershell
docker compose --profile test up -d postgres-test
uv run pytest
docker compose --profile test stop postgres-test
```

The test service uses an in-memory `tmpfs` data directory and never connects to the development
database. Override `TEST_DATABASE_URL` when CI provisions PostgreSQL itself.

## Quality checks

```powershell
uv run ruff format --check .
uv run ruff check .
uv run mypy app
uv run pytest -m "not database"
```

Apply formatting with `uv run ruff format .`.

## Project layout

```text
app/
├── main.py               # Application factory and lifespan
├── api/                  # Health and versioned HTTP routers
├── core/                 # Settings, security, and API errors
├── db/                   # SQLAlchemy base, sessions, queries, models
├── schemas/              # Pydantic request/response contracts
├── services/             # Future business orchestration
├── prompts/              # Future AI prompt definitions
├── workers/              # Future durable job entry points
└── tests/                # Unit and PostgreSQL integration tests
```

## Environment variables

`.env.example` documents every supported setting. Both database URLs must use SQLAlchemy's
`postgresql+psycopg://` driver. CORS origins are supplied as a JSON list. Production startup
rejects the documented placeholder JWT secret.
